# Release v0.5.14

This release carries the control-surface write fence, which `0.5.13` on npm does not. The `0.5.13`
package was published from an earlier commit than the tag now points at; rather than republish a version
that cannot be republished, `0.5.14` is the build that matches the repository.

### Control-surface fence for worker writes

A delegated worker may not write the machinery that judges or signs its own work, **whatever the task
declares**. `REFUSED_PROTECTED_PATH` covers CI definitions (`.github/`), signing material (`keys/`), git
hooks, the gate scripts, the sandbox and policy modules, and the manifest and lockfiles.

This is independent of `targetFiles` on purpose: that check bounds a unit to what its architect declared,
but the architect is the one declaring. A delegation asked to "fix the workflow" can no longer edit
`.github/workflows/ci.yml`, and one asked to "tidy the build" can no longer rewrite `package.json`.

### Refusal vocabulary is now checked

`scripts/check-invariants.cjs` fails CI when the plugin can emit a `REFUSED_*` or
`APPROVAL_REQUIRED_*` code that no reader can look up. Its first run found three undocumented codes,
including `REFUSED_PROTECTED_PATH` on the day it was added. The full vocabulary is in
[`docs/security/red-team-brief.md`](../security/red-team-brief.md).

### Prompt-injection hardening (carried from 0.5.13)

- Injected repository context is wrapped in `<<<CONTEXT_DATA … CONTEXT_DATA>>>`, with a system rule that
  content between the markers is data whose imperatives are part of the file.
- Worker-derived paths and server error bodies are sanitised to one line, bounded, with control characters
  stripped.

### Verification runtime floor

`engines` is raised to `node >=22.23.4`. Below that, verification still runs and prints
`SANDBOX_RUNTIME_UNPATCHED` once: the permission model on 22.19 and earlier has filesystem-allowlist
bypasses (CVE-2026-106071, CVE-2026-58043, CVE-2026-21715), so the sandbox is defence-in-depth there
rather than a boundary.

### Also since 0.5.12

The gate no longer nests `npm run` inside `npm run` (it calls `depcruise` and `eslint` directly), which an
npm re-entry guard in some environments rejects.

### Compatibility

No change to the tool surface, the verdict vocabulary or the attestation schema. The breaking verification
contract announced in `0.5.11` still stands: contracts run as direct `node <script>` and exit `0`/non-zero.
